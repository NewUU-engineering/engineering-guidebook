# Как участвовать

Этот путеводитель не закончен и не должен быть закончен. Он описывает школу, которая ещё строится, людьми, которые ещё приходят. Если вы с чем-то здесь не согласны, ваше несогласие и есть вклад.

Всё это поддерживается открыто по адресу [github.com/NewUU-engineering/engineering-guidebook](https://github.com/NewUU-engineering/engineering-guidebook).

## Публичное согласие

Принятие добровольно, а обязательство, которого никто не видит, — не обязательство. Чтобы публично заявить, что вы следуете этому путеводителю, откройте pull request, добавляющий ваше имя в [`SIGNATORIES.md`](https://github.com/NewUU-engineering/engineering-guidebook/blob/main/SIGNATORIES.md). Студенты, сотрудники и выпускники — все.

Имя можно убрать в любой момент тем же способом и без объяснений.

## Предложение изменений

Откройте [Issue или Pull Request](https://docs.github.com/en/get-started/exploring-projects-on-github/contributing-to-a-project).

### Правила Issue

1. Проверьте, что вы пишете в правильный репозиторий. Всё про эксплуатацию роботов — в [robotics-docs](https://github.com/NewUU-engineering/robotics-docs), всё про содержание учебных курсов — в репозиторий соответствующего курса.
2. Если сообщаете об ошибке, проверьте, что аналогичного Issue ещё нет.
3. Заполняйте заголовок и описание точно.
4. Начинайте заголовок с одного из: `[BUG]`, `[PROPOSAL]`, `[QUESTION]`.

### Правила Pull Request

1. Для мелких изменений — опечатки, форматирование, битая ссылка — Pull Request предпочтительнее Issue.
2. Опишите проблему и предлагаемое исправление. Сошлитесь на номер Issue, если он есть.
3. Прежде чем менять форматирование, убедитесь, что это нужно.
4. Следуйте сложившемуся в репозитории стилю Markdown.
5. Правьте обе языковые версии, если изменение содержательное.

### Спор с принципом

Pull request, меняющий то, что эта школа о себе заявляет, — изменение другого рода, чем исправление опечатки, и выглядеть он должен соответственно. Сначала откройте Issue, скажите, в чём текущий текст неправ, и предложите новую формулировку. Ожидайте, что обсуждение займёт время и пройдёт публично: в этом и смысл, и именно этот механизм не даёт документу превратиться из честного в парадный.

## Стиль

Домашний стиль тот же, что и во всей нашей документации:

- **Конкретное вместо абстрактного.** «Спросите схему оценивания на первой неделе» лучше, чем «студентам следует проявлять инициативу».
- **Указывайте, кто что делает.** Совету без подлежащего никто не следует.
- **Никаких лозунгов.** Если фраза поместилась бы на плакат в коридоре, вычеркните её.
- **Короткие предложения, обычные слова** и не больше прилагательных, чем требует смысл. Значительная часть читателей работает на неродном языке, и ясность — форма вежливости к ним.
- **Ссылайтесь, а не дублируйте.** Если процедура уже существует в другом репозитории, дайте ссылку. Две копии правила означают, что одна из них неверна.
- **Не выдумывайте фактов о школе.** Если канал, политика или программа ещё не согласованы, оставьте помеченную врезку с запросом, а не уверенное предложение, которое окажется ложным.

## Версионирование

Версия и дата стоят в начале [Введения](index.md), под ними — история изменений.

- **Патч** — опечатки, ссылки, уточнения. Версию поднимать не нужно.
- **Минорная** — новый раздел или существенно переписанный текст. Поднимите минорную версию и добавьте строку в историю.
- **Мажорная** — изменение самих ориентиров. Требует предварительного публичного обсуждения в Issue.

## Локальный запуск

### В Docker-контейнере

```bash
git clone https://github.com/NewUU-engineering/engineering-guidebook
cd engineering-guidebook
docker pull squidfunk/mkdocs-material
docker run --rm -it -p 8000:8000 -v ${PWD}:/docs squidfunk/mkdocs-material
```

### В виртуальном окружении Python

```bash
git clone https://github.com/NewUU-engineering/engineering-guidebook
cd engineering-guidebook
python3 -m venv venv
source venv/bin/activate
pip install mkdocs-material "mkdocs-static-i18n[material]"
mkdocs serve
```

Сайт будет доступен по адресу `http://127.0.0.1:8000`.

Пуш в `main` запускает workflow `Deploy Docs`, который выполняет `mkdocs gh-deploy --force` и публикует сайт на GitHub Pages из ветки `gh-pages`.
